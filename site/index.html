Routing modes

Use the policy that fits the job.

Adaptive routing is the default, not a requirement. A production chain, a paid subscription pool and a reproducible test run do not need the same policy. Change modes from the panel and apply them on the next call.

01

Adaptive

Learns from quality, health, latency and quota. It keeps exploring instead of locking onto the first provider that worked.

02

Tier priority

Exhausts tier 1 before tier 2. Learning still decides the order inside each tier.

03

Fixed list

Uses the exact chain order you set and moves on only after failure or temporary unavailability.

04

Round robin

Rotates the first available provider after each real attempt. Opening the panel never moves the cursor.

    Reinforced calls

    Spend preferred capacity first. Keep the fallback.

    Build an ordered queue from any configured account. Put subscriptions first, mix in credits or free accounts, then return to the normal route only if every preferred account fails.

    Available to OpenAI and Anthropic clients with X-RobinBandit-Mode: reinforced.

    Operational panel

    Answers before configuration becomes guesswork.

    Provider authentication and client connection are separate states. The panel names who can answer, which tool has actually sent a request, what was consumed and why a provider moved in the queue.

    What is measured

    Enough detail to act, without fake precision.

    Usage is stored under ~/.robinbandit. Tokens are counted whenever a provider reports them. Dollar cost is stored only when the provider includes it, because a stale pricing table is worse than an honest unknown.

    Adaptive loop

    A decision that changes with evidence.

    In adaptive mode, quality and operational health are separate Beta posteriors. A successful HTTP response does not automatically mean a good answer, and old evidence decays so the router can recover when conditions change.

    01 / ORDER

    Score

    Combine quality, latency, health, tier, cost class, quota and open calls.

    02 / CALL

    Try

    Call providers in order and preserve a final fallback when everything is degraded.

    03 / OBSERVE

    Classify

    Distinguish rate limit, credit exhaustion, timeout and other failures.

    04 / LEARN

    Update

    Record health immediately and quality when your application sends feedback.

    Quickstart

    One process, three client protocols.

    Providers appear in the active chain only when selected and usable. Codex CLI enters through the Responses API; ChatGPT Codex is a separate outbound provider that can answer through its authenticated CLI session.

    # install the server and provider adapters
pip install "robinbandit[server,yaml,providers]"

robinbandit serve

# panel
http://localhost:8000/painel

# OpenAI-compatible endpoint
http://localhost:8000/v1/chat/completions

# Responses API (Codex CLI)
http://localhost:8000/v1/responses

# Anthropic-compatible endpoint
http://localhost:8000/v1/messages
