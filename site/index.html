A fixed fallback chain has no memory: the provider that just returned a 429 is still first in line on the next call. RobinBandit reorders providers from what actually happened — quality, latency, health and quota — and shows you why.

Why RobinBandit

A fallback list only knows the order you typed.

Provider A fails, you try B, then C. Next call, A is first again — even though it has been slow for an hour, even though its credit ran out ten minutes ago. The enemies here are quota, cost, latency and quality drift, and none of them announce themselves in a status code.

↯

Evidence, not order

Every call updates a Beta posterior for that (context, provider). The next decision is drawn from what the router has actually observed.

◎

One cell per context

A context string splits learning: codigo and triagem can settle on different providers, because they are different jobs.

⇄

Degradation is a signal

429s, exhausted credit and latency spikes push a provider down and into cooldown — without removing it from the chain if everything else fails too.

How it works

One score, eight signals, sampled rather than averaged.

On every order() each provider gets a score. Quality and health are Thompson-sampled from independent Beta posteriors — the draw is what keeps the router exploring instead of locking onto the first thing that worked.

score = w_q * quality_thompson + w_l * (1 - latency_norm) + w_s * health_thompson + tier_bonus + priority_bonus + profile_bonus - cost_penalty - quota_penalty - inflight_penalty
qualityThompson sampling per (context, provider)
latencyPeak EWMA — a spike lands now, recovery is gradual
healtha separate Beta, so an HTTP 200 never raises quality
quotaused when the provider reports what is left
inflightopen calls, capped at 0.15 — a nudge, not a balancer
tier & priorityyour declared preference, as bonus or as barrier
costa penalty per declared cost_class
profileper-task preference: analysis, coding, and so on
01 / ORDER
Score the chain Each provider is scored for this context. Providers in cooldown sink to the end, but stay reachable if the rest fail too.
02 / CALL
Try in order Models inside a provider are tried top-down, stopping at the first one that answers.
03 / OBSERVE
Classify the outcome Rate limit, exhausted credit, timeout — read from a table, because the wording changes whenever a provider feels like it.
04 / LEARN
Reinforce, with decay Posteriors update at decay = 0.99 under a mass ceiling, so old evidence fades and recent change lands.

No torch, no sklearn, no numpy. This is Bayesian reinforcement learning, and the core runs on the Python standard library alone. Read how it learns →

    The panel

    It shows the decision. It does not recompute it.

    robinbandit serve ships a panel at /painel, served by the package itself. Everything on it comes from the router — a panel that does its own math shows one thing while the router decides another. (The UI in these shots is Portuguese.)

    Quickstart

    Point a tool at it, or import it.

    The factory catalog ships inside the package, so serve comes up with no YAML at all. A provider with no key in the environment simply is not built.

    Serve — endpoint and panel
    # the core is dependency-free; extras add the rest
pip install "robinbandit[server,yaml,providers]"

robinbandit serve
# panel     http://localhost:8000/painel
# endpoint  http://localhost:8000/v1/chat/completions

# then send any OpenAI-compatible client here.
# `model` is the bandit CONTEXT, not a model name:
#   model="codigo"   learns in one cell
#   model="triagem"  learns in another
    Import — router and chain
    from robinbandit import ChainProvider, ProviderRouter

router = ProviderRouter(
    providers={
        "groq":   {"tier": 1, "quality": 0.75},
        "gemini": {"tier": 1, "quality": 0.80},
        "demo":   {"tier": 9, "quality": 0.05},
    },
    last_resort="demo",
)

chain = ChainProvider([groq, gemini, demo], router)

response = await chain.complete(
    messages, context="auditoria",
)

# an HTTP 200 is not the same as a good answer
router.reward_quality(
    "groq", context="auditoria", good=True,
)

    Declare the chain — config/universal.yaml
    routing:
  strategy: adaptive     # or: tier
  last_resort: fallback
  chain_order: [groq, gemini, claude_code,
                cerebras, openrouter, ollama]

providers:
  groq:
    cost_class: free_preferred
  claude_code:
    auth_type: claude_cli   # no api key
  ollama:
    cost_class: local

# secrets are never in here, only the NAME of
# the env var. the value lives in the vault.
    The catalog

    41 providers, and not one of them opts in by itself.
